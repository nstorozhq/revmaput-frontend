# РевмаПуть

Фронтенд учебного портала по ревматологии. Этот проект реализует задачу роли «Фронтенд / UX» на первый спринт из разделов 4.1 и 4.3 дополнения № 1.

Главная открывается сразу в приложении. С экрана «Обзор» посетитель выбирает анкету симптомов или личный кабинет, переходит в библиотеку и может раскрыть описание скрининга. Навигация по разделам находится слева на компьютере и внизу на телефоне. При проектировании использованы паттерны из раздела [Patient Portals в подборке Koru UX](https://www.koruux.com/50-examples-of-healthcare-UI/).

## Запуск

Нужен Node.js 22.12 или новее.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite, обычно `http://localhost:5173`. Для проверки TypeScript и сборки выполните `npm run build`. Для просмотра собранной версии выполните `npm run preview`.

Для статического стенда раздавайте содержимое `dist` из корня сайта. Хостинг должен отдавать `index.html` при прямом запросе маршрута приложения, например `/screening`. Реальные файлы в `/assets/` раздаются напрямую.

## Что показать на демо

1. На главной нажмите «Открыть анкету». На странице `/screening` прочитайте дисклеймер и отметьте обязательное подтверждение. После «Начать анкету» выберите ответ на каждом из трёх вопросов. Вернитесь назад и проверьте, что предыдущие варианты остаются выбранными. Ответ «Да» на В1 показывает демонстрационный экран срочности.
2. Вернитесь на главную и нажмите «Открыть кабинет». Откроется страница кабинета `/account`.
3. Из меню перейдите в библиотеку `/library`. Страница показывает четыре запланированные темы.
4. Откройте «Справку». В ней находятся «Как это работает», «Медицинский совет» и раздел «О сервисе» с дисклеймером и правовыми ссылками.
5. На узком экране смените раздел через нижнюю навигацию. С клавиатуры проверьте видимый фокус, пропуск к основному содержанию и раскрытие справки.

Анкета показывает вступление и три вопроса из дополнения к ТЗ в порядке A1, A6, В1. В1 сформулирован как прямой вопрос к пациенту с сохранением исходных условий. Нумерация показывает позицию в демо. Выбор хранится в памяти приложения до перезагрузки вкладки или снятия подтверждения на вступлении. Ответы не отправляются на сервер и не используются для расчёта результата. Внутри каждого вопроса показан черновой дисклеймер. Кабинет и библиотека демонстрируют навигацию спринта 1. Правовые маршруты `/privacy` и `/terms` содержат статус учебной версии.

## Стек и структура

- React и TypeScript для общих элементов навигации и страниц. Vite для локального запуска и сборки. React Router для переходов и прямых URL.
- React Aria Components для раскрываемой справки, подтверждения, вариантов ответа и индикатора прогресса. Оформление задаётся собственным CSS, шрифт Manrope поставляется локально.
- `src/App.tsx` содержит маршруты, общую оболочку, обзор и страницы разделов. Шаги анкеты находятся в `src/screening/Screening.tsx`. Формулировки, варианты ответа и настройка красного флага находятся в `src/screening/questions.json`. Иллюстрация библиотеки в `src/assets/library.webp` сгенерирована встроенным ImageGen и оптимизирована до 21 КБ.

## Интеграция и следующие этапы

- **Спринт 1.** Тимлид утверждает стек и адреса маршрутов в командном репозитории. Для командного прогона нужен API гостевой сессии. С архитектором и бэкендом нужно согласовать OpenAPI: момент создания сессии, входные и выходные поля, повторную попытку, обработку сетевых ошибок и способ возобновить прохождение. После подключения проверить запись сессии в БД на синтетических данных.
- **Спринты 2–3.** Вводный экран с обязательным подтверждением, шаги, валидация, прогресс, сохранение ответов, экран срочности и экран результата. Вопросы и варианты приходят по JSON-контракту, результат определяет сервер. При ответе, вызвавшем красный флаг, интерфейс сразу открывает экран срочности. Продолжение прохождения сохраняет приоритет результата `red_flag`.
- **Спринт 4.** Скачать PDF результата, показать четыре рецензированные статьи и довести до готовности страницу «К какому врачу и с чем идти», которая входит в MVP.
- **Дальше.** Подключить ML-пояснение и функции кабинета по плану команды. Согласовать объём кабинета для защиты: в основном ТЗ он указан во второй волне и в перечне материалов к защите.

Для подключения анкеты нужны полный первоисточник с таблицами 22 вопросов, весами и сценариями A–D, согласованный JSON и утверждённые формулировки. Глобальный дисклеймер находится в константе `disclaimer` в `src/App.tsx`. Его текст для учебного демо рабочий и подлежит замене после согласования с куратором. Сведения о медсовете и тексты правовых страниц потребуются от команды.
